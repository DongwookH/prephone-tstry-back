# 테넌트 세부 가이드 · 키워드 백오피스 입력 화면

작성일: 2026-07-27
상태: 승인됨 (사업주 확인 완료)

## 배경

멤버(테넌트)는 지금 전용 구글 시트의 `guide` 탭을 직접 열어 8개 섹션을 채워야 한다.
섹션은 큰 자유 텍스트 덩어리고, `links`는 `"이름: URL"` 형식을 손으로 맞춰야 한다.
키워드도 마찬가지로 `keywords` 탭을 직접 편집해야 한다.

첫 테넌트(2026-07-27 등록)가 전 항목 미작성 상태이며, 이 상태에서는 생성 크론이
해당 테넌트를 건너뛴다. 시트 편집은 비개발자에게 진입 장벽이므로 백오피스 화면에서
직관적으로 입력할 수 있어야 한다.

## 목표

1. 멤버가 **구글 시트를 열지 않고** 백오피스만으로 온보딩을 끝낼 수 있다.
2. 입력 칸이 도메인 용어(판매점명·카카오톡 채널·개통 사이트)로 되어 있어 무엇을
   넣어야 하는지 고민할 필요가 없다.
3. 기존 글 생성 파이프라인과 오너 동작은 **무회귀**.

## 비목표 (YAGNI)

- 키워드 자동 추천 — 별건으로 분리
- 오너용 가이드 편집 화면 (오너 규칙은 코드·CLAUDE.md에 고정)
- 가이드 변경 이력·되돌리기

## 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 입력 칸 단위 | 하이브리드 — 필수는 도메인 전용 칸, 선택은 자유 텍스트 | 초심자는 필수만, 고급 사용자는 더 깊이 |
| 시트 처리 | 폼이 정식 창구, 시트도 계속 열어둠 | 긴 FAQ 붙여넣기 등은 시트가 편함 |
| 저장 방식 | **A안** — `guide` 탭에 행 추가로 세분화 | 시트 단일 저장소 유지, 왕복 무손실, 사람이 읽힘 |
| 화면 위치 | 사이드바 전용 메뉴 + 대시보드 배너 | 첫 사용자가 방치되지 않게 |
| 범위 | 가이드 + 키워드 둘 다 | 둘 다 있어야 시트를 안 열어도 됨 |

### 저장 방식 대안 검토

- **B안 (기존 4섹션에 조립·재파싱)**: 스키마 변경이 없지만, 사용자가 시트에서 자유
  형식으로 고치는 순간 폼이 값을 잃는다. "시트도 계속 열어둔다"는 결정과 충돌 → 기각.
- **C안 (JSON 한 줄)**: 구조는 자유롭지만 시트가 사람이 못 읽는 덩어리가 된다.
  시트를 유지하는 의미가 사라짐 → 기각.

## 데이터 모델

`guide` 탭 열 구조는 유지한다: `A section / B 설명 / C content / D updated_at`.
행만 추가한다 (기존 행 삭제·이름 변경 없음).

```
brand_name    (필수)   판매점명
link_kakao    (필수*)  카카오톡 채널 링크
link_site     (필수*)  개통 사이트 링크
phone                  전화번호
hours                  영업시간
plans         (필수)   요금표
company       (필수)   회사 소개 — 위 항목으로 자동 조립 + 직접 보완
links                  기존 자유형식 (하위호환 · 고급 영역)
personas               선택 (변경 없음)
banned_words           선택 (변경 없음)
extra_rules            선택 (변경 없음)
faq                    선택 (변경 없음)
```

\* `link_kakao`·`link_site`·`links` 중 **최소 하나**는 있어야 한다. 글의 히어로 버튼이
링크에서 만들어지므로 하나도 없으면 버튼 없는 글이 나간다.

### 조립 규칙 (`loadTenantGuide`)

읽는 쪽에서 조립하므로 **글 생성 파이프라인(`post-generator.ts`, `generate-tenants.ts`)은
수정하지 않는다.** `TenantGuide` 타입도 그대로 유지된다.

- `links[]` = `link_kakao`(라벨 "카카오톡 상담") + `link_site`(라벨 "개통 신청")
  + 기존 `links` 행 파싱분. 순서는 이 순서.
- `company` = 자동 조립 문장 + `company` 원문.
  자동 조립 문장은 채워진 항목만 이어붙인다:
  `"{brand_name} — 전화 {phone}, 영업시간 {hours}"`.
  전부 비면 조립 문장 없이 원문만 쓴다.
- 나머지 섹션은 기존과 동일.

### 필수 검증 (`missingRequiredGuideSections`)

반환값은 **폼 필드 이름 기준**으로 바꾼다 (사용자에게 그대로 보여주기 위함):

- `brand_name` 없음 → `"brand_name"`
- `link_kakao`·`link_site`·`links` 모두 없음 → `"links"`
- `company`가 자동 조립분·원문 모두 비어 있음 → `"company"`
- `plans` 없음 → `"plans"`

기존 호출부(`generate-tenants.ts`)는 문자열 목록을 로그에만 쓰므로 영향 없음.

## 화면

### `/guide` (신규, 멤버 전용)

- 상단: 진행률 (`필수 4개 중 n개 완료`) + 미완성 시 경고 배너
- 필수 섹션: 판매점명 / 카카오톡 채널 링크 / 개통 사이트 링크 / 전화번호 /
  영업시간 / 요금표
- 접히는 선택 섹션: 타깃 독자 · 금지어 · 추가 규칙 · FAQ
- 맨 아래 「고급: 직접 입력」 — `company` 원문, `links` 자유형식.
  폼이 못 알아보는 시트 값이 여기에 원문 그대로 노출된다.
- 오너가 접근하면 `/settings`로 리다이렉트

### 사이드바

멤버 메뉴에 「내 가이드」 추가. 필수 미완성이면 빨간 점 배지.
오너 메뉴는 변경 없음.

### 대시보드

멤버 + 필수 미완성일 때만 상단 배너: "가이드를 완성해야 글이 생성됩니다 → 작성하기".
완성 상태면 배너 없음.

### `/keywords` (멤버 개방)

현재 멤버는 `redirect("/")`로 차단되어 있다. 본인 시트로 스코프해 개방한다.
- 목록·추가·비활성화만 노출
- 오너 전용 도구(네이버 검색광고 API 발굴, 스레드 키워드 등)는 숨김

## 서버 액션

`app/(dashboard)/guide/actions.ts` 신설. 기존 `settings/actions.ts`의 `scopedSheetId()`
패턴을 그대로 따른다 — **매 호출 `getViewerContext()`로 세션 기준 재확인**하고
클라이언트가 보낸 시트 ID는 신뢰하지 않는다.

- `saveGuideAction(fields)` — `guide` 탭 upsert (섹션 행이 없으면 추가), `updated_at` 갱신
- 키워드는 기존 `keywords/actions.ts`에 스코프 분기 추가

저장은 **부분 허용**. 필수가 비어도 저장되고 경고만 표시한다. 중간 저장 후 나중에
이어서 작성할 수 있어야 한다.

## 에러 처리

- URL 형식 검증: `http://` 또는 `https://`로 시작하지 않으면 저장 거부 + 필드별 메시지
- 시트 접근 실패: 액션이 `{ ok: false, error }`를 반환하고 폼이 인라인 표시
- 시트 미발급 멤버(`sheetId === ""`)는 기존 "전용 시트 발급 대기 중" 화면
- 폼이 파싱하지 못한 기존 값은 **삭제하지 않고** 「고급」 영역에 원문 유지
